## 5. 문제 발생 및 해결

### P-01. 머지 중 Game.java 충돌

- 확인일: 2026-09-29, 대화 기록 기준.
- 상황: games에 origin/develope를 병합하며 같은 파일이 양쪽에서 수정됨.
- 차이: 작업 브랜치는 빈 클래스와 `main.java.tetris.games` 선언, 통합 브랜치는 상태 전환 구현과 `tetris.games` 선언.
- 해결: 상태 전환 구현을 유지하고 올바른 패키지 선언으로 충돌 표시 제거.
- 검증: Game·GameState 컴파일 성공, 미해결 경로 없음 확인.
- 상태: 충돌 해결 확인. 이후 사용자가 로그인 후 동기화 성공을 알림. 해당 커밋 ID는 추가 필요.
- 재발 방지: 같은 파일 수정 전 브랜치 변경 확인, 패키지와 소스 루트 규칙 공유.

### P-02. Gradle 테스트 프로세스를 실행하지 못함

- 환경: Windows, 한글이 포함된 사용자·프로젝트 경로, Java 21, Gradle 8.14.3.
- 증상: `worker.org.gradle.process.internal.worker.GradleWorkerMain`을 찾지 못함; 소스 컴파일은 통과.
- 진단: Windows 경로와 Java 실행 인자 파일의 인코딩 문제로 판단. 인코딩 호환 옵션 적용 전후 결과로 확인.
- 해결: `gradle.properties`에 `org.gradle.jvmargs=-Dfile.encoding=COMPAT` 적용. 소스 컴파일은 UTF-8 유지.
- 검증: 별도 명령행 옵션 없이 `./gradlew.bat --no-daemon test --rerun-tasks` 성공.
- 상태: 로컬 환경 해결. 팀원 PC에서도 기본 테스트 명령 확인 필요.

### P-03. VS Code에 Java 오류 279건 표시

- 증상: `javafx`, `org.junit`, `KeyCode`, `Text` 등을 찾지 못함. 일부 테스트에 잘못된 예상 패키지 경로 표시.
- 실제 빌드: Gradle 컴파일과 테스트는 통과한 상태.
- 진단: Gradle 추가 전의 일반 Java 프로젝트 분석 정보가 남아 의존성과 소스 경로를 잘못 인식한 것으로 판단.
- 시도: 프로젝트 가져오기, 언어 서버 재시작, 전체 Java 컴파일로는 오류가 재발함.
- 해결: 사용자 동의 후 `Java: Clean Java Language Server Workspace` → `Reload and delete` 실행.
- 검증: Gradle 재가져오기 완료 후 `Java: Ready`, 문제 목록 0건 확인.
- 영향 범위: Java 분석 캐시 재생성. 소스 코드·Git 기록은 변경하지 않음.
- 상태: 해결.
- 재발 방지: 프로젝트 루트를 열고 Gradle 설정·Wrapper를 함께 공유. 빌드는 통과하지만 IDE 오류만 남을 때 캐시 초기화 검토.
