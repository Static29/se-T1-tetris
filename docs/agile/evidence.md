# 근거·용어·작성 원칙

## 사용한 자료

1. 저장소 [Static29/se-T1-tetris](https://github.com/Static29/se-T1-tetris)의 Git 커밋·병합 이력.
   2026-10-26 `git fetch origin` 이후 `origin/develope=acab7f5`를 기준으로 조사했다.
2. 커밋의 실제 변경 파일과 메시지. PR 번호는 병합 커밋 메시지로 확인했고, GitHub 웹의 승인·댓글은 별도로 확인하지 않았다.
3. 기존 09/29·10/03·10/08 협업 문서. 환경 문제의 상세 근거는 당시 문서의 기록 수준을 넘어서 추정하지 않는다.
4. 사용자가 제공한 박제상 개발노트 01~09의 요약 텍스트. 원본 PDF 9개를 직접 읽은 결과가 아니며 설계 배경의 보조 자료로 사용했다.
5. 사용자가 설명한 실제 3인 업무 분담 및 개발 과정.
6. 현재 작업 트리의 배포 검증과 [커버리지 측정 기록](../testing-and-coverage.md).

## 날짜와 상태

커밋 작성 날짜를 작업 기록일로 사용한다. 실제 착수일·완료 시각이나 회의 시각을 의미하지 않는다.
예: `c9d9c76`은 10/16에 작성됐지만 PR #11 병합은 10/23이다.
일부 기록 구간이 비어 있어도 그 기간에 일을 하지 않았다고 해석하지 않는다.
stash 및 GitHub Desktop 임시 저장 커밋은 제품 산출물 이력에서 제외했다.

단계 번호 1~5는 사후 정리 순서다. 과거 계획·스프린트 약속·회고 발언을 새로 만들어 넣지 않는다.
'결과와 개선점'은 기록을 보고 현재 정리한 분석이며 실제 회의록과 구분한다.

테스트 수는 해당 시점의 전체 실행 수이며 합산하지 않는다. 개발노트의 362개와 현재 365개는 서로 다른 시점의 기록이다.
배포·아이콘·JaCoCo는 이번 문서 작성 시 미커밋이므로 연결된 PR이 없다고 명시한다.
