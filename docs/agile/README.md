# 주차별 Agile 운영 안내

3인 팀에 맞춰 1주 단위로 계획·구현·검증·개선을 반복합니다.
정식 Scrum의 모든 역할과 행사를 도입하기보다, 짧은 목표와 확인 가능한 결과를 관리합니다.
교수자의 요구사항을 우선하며, 팀이 실제로 수행한 활동만 기록합니다.

## 문서 구성

| 문서 | 관리하는 내용 |
| --- | --- |
| [team.md](team.md) | 역할, 담당 파일, 협업 경계 |
| [backlog.md](backlog.md) | 전체 작업, 요구사항 연결, 우선순위, 진행 상태 |
| [week-template.md](week-template.md) | 매주 복사할 기록 양식 |
| [weeks/2026-09-29.md](weeks/2026-09-29.md) | 현재 확인된 진행 내역; 실제 주차와 기간은 팀 확인 필요 |

## 매주 진행하는 순서

1. **계획:** 이번 주에 시연할 수 있는 목표 하나를 정합니다. 전체 작업 목록에서 감당할 수 있는 작업을 선택하고 담당자·검증 기준을 적습니다.
2. **진행:** 각자 작업일에 완료한 일, 다음 작업, 막힌 점을 짧게 기록합니다. 매일 회의를 열 필요는 없습니다.
3. **협업:** 좌표·메서드·데이터 형태가 바뀌면 관련 담당자와 먼저 합의하고 주차 문서에 남깁니다.
4. **리뷰:** PR과 테스트 결과를 확인하고 실제 동작을 시연합니다. 구현 완료와 통합 완료를 구분합니다.
5. **회고:** 잘된 점, 어려웠던 점, 다음 주 개선 행동을 기록합니다. 개선 행동에도 담당자와 확인 시점을 정합니다.

## 새 주차 문서 만들기

1. `week-template.md`를 복사해 `weeks/YYYY-MM-DD.md`로 저장합니다. 날짜는 해당 주의 시작일입니다.
2. 제목·주차·기간·주간 목표를 채웁니다. 수업 주차를 모르면 `확인 필요`로 둡니다.
3. 아래 주차 목록에 링크를 추가합니다.
4. 선택한 작업을 `backlog.md`에서 가져오고 GitHub Issue 링크를 연결합니다.
5. 주중에는 같은 문서를 갱신하고, 주말에는 리뷰·회고와 이월 항목을 작성합니다.

문서 파일명은 날짜로 구분하므로 수업 주차를 정정해도 파일을 바꿀 필요가 없습니다.
현재의 `2026-09-29.md`는 진행 현황을 옮겨 적은 초안이며, 주간 계획이나 실제 회의를 소급해서 꾸민 기록이 아닙니다.

## 상태 기준

| 상태 | 의미 |
| --- | --- |
| 대기 | 해야 할 작업으로 등록됨 |
| 진행 | 담당자가 구현 또는 조사 중 |
| 검토 대기 | 구현·자체 검증 후 팀 리뷰 또는 통합을 기다림 |
| 차단 | 진행을 막는 의존성·문제가 있음; 원인과 다음 행동 필수 |
| 완료 | 수락 기준 충족, 검증 증거와 리뷰 기록 존재, 필요한 통합 완료 |

`develope` 통합을 보류했다면 로컬 테스트가 통과해도 `검토 대기`로 기록합니다.
조사·문서 작업처럼 코드 병합이 필요 없는 작업은 결과와 검토 기록으로 완료를 판단합니다.
팀원의 작업 상태를 보지 못했다면 추측하지 않고 `확인 필요`로 적습니다.

## 완료 기준과 증거

- 연결된 요구사항 또는 팀이 승인한 추가 기능의 수락 기준을 만족합니다.
- 기능에 필요한 테스트를 실행하고 명령·결과·대상 커밋을 기록합니다.
- UI는 조작 순서와 실제 확인 결과를 남깁니다. 자동 테스트 통과와 수동 확인을 구분합니다.
- PR 리뷰와 대상 브랜치 통합 여부를 확인합니다.
- 미구현·제약·후속 작업을 명시하고 관련 문서를 갱신합니다.

게임 전체의 Line Coverage 목표(요구사항 원문 50~70% 이상)는 별도로 확인해야 합니다.
테스트 개수가 많다는 이유로 커버리지나 모든 요구사항이 충족됐다고 판단하지 않습니다.

## GitHub와 연결하기

`요구사항 → 작업 ID → GitHub Issue → 작업 브랜치 → PR → 커밋 → 테스트 결과`를 연결합니다.

- 이 문서의 `TASK-001` 같은 ID는 문서 내부 식별자이며 실제 GitHub Issue 번호가 아닙니다.
- Issue를 만든 뒤 실제 링크를 붙입니다. 아직 없는 번호·URL은 만들지 않습니다.
- Issue/PR에서 최신 진행 상태를 관리하고, 주차 문서는 해당 주의 결과를 보존합니다.
- `build/`의 테스트 보고서는 Git에서 제외되므로 명령·결과·커밋을 문서에 적고, 필요하면 PR 또는 CI 결과 링크를 남깁니다.
- 이전 주의 결정을 바꿀 때는 원문을 지우지 않고 새 결정과 변경 이유를 기록합니다.
- 공유 문서 수정은 작게 커밋하고, 관련 주차 문서를 리뷰한 뒤 통합합니다.
