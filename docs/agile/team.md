# 팀 역할과 협업 경계

2026-10-08 정승우가 전달한 팀원 이름과 업무 분담을 반영했습니다. GitHub 계정은 별도 확인이 필요합니다.

| 이름 | 역할 | 책임 | 주요 영역 |
| --- | --- | --- | --- |
| 정승우 | 팀장 · 게임 코어 관리 | 게임 진행·상태·입력 연결, 난이도 설정, 난이도에 따른 게임 시스템 분기 및 통합 | `Main.java`, `games/`, `ui/`의 게임코어 연결, 공통 환경 |
| 박제상 | 보드 구현 | 보드·충돌·고정·행 삭제, 블록 낙하 속도 조절, 줄 삭제 애니메이션, 삭제 줄 10개 카운트 및 아이템 반환 함수 호출 | `board/`, 보드 표시·속도 연동 |
| 박서상 | 테트로미노 | 블록 종류·모양·좌표·회전, 난이도별 등장 가중치, 아이템 생성·동작 전반 | `block/`, 아이템 로직 |
| 다시냠 | 스코어 및 간단한 조정 | 점수 배분·계산, 난이도별 점수 적용, M 아이템 점수 배율 반영, 간단한 조정 | 점수·기록 관련 코드; 간단한 조정의 세부 범위는 작업별 협의 |

경로는 `src/main/java/tetris/` 기준이며 테스트는 `src/test/java/tetris/`에 대응합니다.
기능 책임을 기준으로 분담하며, 공용 파일 수정은 관련 담당자와 조율합니다.

## 협업 경계

| 연결 지점 | 담당 경계 | 추가 합의 사항 |
| --- | --- | --- |
| 난이도 | 정승우가 설정·게임 시스템 분기를 관리하고 각 영역에 전달 | 전달 형식, 적용·초기화 시점 |
| 블록 생성 | 박서상이 난이도별 등장 가중치 적용 | 난이도별 가중치 수치 |
| 낙하 속도 | 박제상이 속도 조절을 맡고 정승우가 게임 진행과 연결 | 줄 삭제에 따른 속도 증가량: Easy 일반 대비 0.8배, Hard 1.2배; 낙하 간격 환산 방식 |
| 아이템 등장 | 박제상은 삭제 줄 10개 카운트와 아이템 반환 함수 호출까지, 박서상은 아이템 생성·동작 구현 | 반환 형식, 잔여 카운트, 아이템으로 제거한 줄의 포함 여부 |
| 제거 이펙트 | 박제상이 삭제 줄 애니메이션 구현 | 일반 삭제·아이템 삭제 연결 및 입력·하강 처리 시점 |
| 점수 | 다시냠이 난이도별 점수 계산, 박서상이 M 아이템 발동 처리 | M 배율·지속시간·점수 전달 방식 |
| 이동·회전·고정 | 정승우가 진행·입력 연결, 박제상이 배치·충돌·고정, 박서상이 모양·회전 담당 | 좌표 변환과 호출 인터페이스 |
| Next·Hold | 정승우가 게임 진행과 미리보기 연결, 박서상이 블록 생성·모양 제공 | 생성·교환·고정 후 갱신 시점 |

아이템 종류는 L(라인 지우기), 무게추(모양 그대로), F(세로줄 하단 빈 공간 메우기), B(무작위로 차 있는 공간 약 4칸 제거), M(점수 배율 블록)입니다.
세부 동작과 수치는 [백로그](backlog.md)의 미결 사항을 먼저 합의합니다.

## 문서와 리뷰 운영

- 각 담당자는 본인 작업과 문제 해결 내용을 주차 문서에 기록합니다.
- 회의 진행자와 기록자는 주차마다 정하며, 팀장이 항상 맡는 것으로 가정하지 않습니다.
- 인터페이스를 바꾸는 PR은 해당 코드를 사용하는 팀원이 함께 리뷰합니다.
- 다른 담당자의 파일을 수정해야 한다면 이유와 범위를 먼저 합의합니다.
- 구현 완료와 테스트·리뷰·통합 완료를 구분합니다.
- 통합 브랜치는 기존 문서 기준 `develope`이며 이름 변경은 별도 합의합니다.
- 역할 변경 시 적용 날짜와 이유를 아래에 추가합니다.
