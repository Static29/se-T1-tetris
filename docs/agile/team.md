# 팀 역할과 협업 경계

사용자가 확인한 실제 개발 참여 및 업무 분담을 정리한다. 담당은 팀 역할이며, 개별 커밋의 작성·병합 이력은 각 결과 문서에 별도로 연결한다.

| 담당자 | 담당 영역 | 실제 작업 범위 |
|---|---|---|
| 박제상 | 보드 | Board·좌표·충돌·고정·행 삭제, SRS 충돌 연결, 블록 선택·생성·속도·고정 유예, 아이템의 보드 효과, 보드 테스트 |
| 박서상 | 테트로미노(블록) | 7종 모양·위치·회전, SRS 회전 후보, 아이템 종류·부착 위치·특수 모양·생성 팩토리, 블록 테스트 |
| 정승우 | 게임 시스템·사용자 인터페이스(UI) | 게임 진행·입력·Next/Hold, 보드·블록 통합, 점수·스코어보드, 설정·저장, 화면·애니메이션, 빌드·배포·커버리지 |

경로 기준: `src/main/java/tetris/`. 테스트는 `src/test/java/tetris/`에 대응한다.

## 모듈 연결

| 연결 지점 | 책임 분리 |
|---|---|
| 이동·회전 | Block이 좌표·후보를 제공, Board가 충돌을 검사, Game이 입력·진행에 연결 |
| 아이템 | block이 아이템 데이터를 생성, board가 고정·삭제 결과를 반환, games/score가 점수와 등장 시점을 관리 |
| 속도·난이도 | board/FallSpeed가 속도를 계산, Game이 난이도를 전달하고 UI·점수에 배율 적용 |
| 표시 | Board는 고정 셀 데이터, Game은 이동 중 블록·미리보기 데이터, UI는 색·문자·이펙트 표시 |
| 검증 | 각 담당의 단위 테스트와 Game 통합 테스트, 공통 Gradle 검증·배포 검사 |

기존 담당 API를 우선 재사용한다. Game 연결 문제를 해결하기 위해 board 내부 구현을 불필요하게 변경하지 않는다.
공유 API 변경이 필요하면 영향받는 호출부·테스트·담당을 기록한다. 이 원칙은 병합 충돌을 줄이기 위한 현재 운영 기준이다.

Git에는 `Rusan`, `park sang eon`, `sw209`, `Seungwoo Jeong` 등의 작성자 표시가 있다.
실명 분담은 사용자 확인과 개발노트, 해당 모듈의 변경 이력을 함께 근거로 정리했다.
병합 커밋 작성자를 그 PR 전체 기능의 구현자로 간주하지 않는다.
