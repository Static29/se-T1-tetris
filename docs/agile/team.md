# 팀 역할과 협업 경계

사용자가 전달한 초기 분담 기준입니다. 팀원 실명, GitHub 계정, 최종 인터페이스는 팀 회의 후 채웁니다.

| 역할 | 이름 / GitHub | 책임 | 주요 영역 |
| --- | --- | --- | --- |
| 팀장 | 정승우 / 계정 확인 필요 | 기본 구조, 게임 진행, UI·입력, 하강 타이밍, 일시정지·재개, 통합 | `Main.java`, `games/`, `ui/`, Gradle 설정 |
| 팀원1 | 입력 필요 | 보드 생성, 칸 상태, 배치 가능 여부, 충돌 검사, 블록 고정, 행 삭제 | `board/` 및 보드 테스트 |
| 팀원2 | 입력 필요 | 블록 종류·모양·좌표·회전, 생성 로직 제공 및 보드 담당자와 협업 | `block/` 및 블록 테스트 |

위 파일 경로는 `src/main/java/tetris/` 기준입니다. 테스트는 `src/test/java/tetris/`에 대응시킵니다.
초기 분담에는 팀원1의 생성 속도·조작 업무도 언급됐으므로, 아래 연결 경계는 팀 전체 합의가 필요합니다.

## 통합 시 합의할 경계

| 연결 지점 | 현재 상태 / 권장 경계 | 확인할 담당자 |
| --- | --- | --- |
| 좌표 | `Position`은 `(row, col)`, `TetrominoType`은 `{x, y}`. `row=y`, `col=x`로 변환 | 전원 |
| 이동·회전 | 입력은 UI, 진행 판단은 Game, 배치 가능 여부는 Board, 모양 변환은 블록 | 전원 |
| 자동 하강 | 타이밍·속도는 Game에서 관리하고 충돌 검사는 Board에 요청하는 안 | 팀장·팀원1 |
| 화면 표시 | `BoardView`는 UI 담당. 보드·블록 로직에서 JavaFX 창을 만들지 않는 방향 | 전원 |
| Next·Hold | Game에서 종류와 순서를 관리하고 UI에서 표시. 블록 모양은 팀원2 데이터 사용 | 팀장·팀원2 |
| 고정 이후 | 실제 고정 완료 후 `Game.advanceAfterLock()` 호출; 생성 위치·회전 초기화와 Game Over 검사는 추가 연결 필요 | 전원 |

## 문서와 리뷰 운영 제안

- 각 담당자는 본인 작업과 문제 해결 내용을 주차 문서에 작성합니다.
- 회의 진행자와 기록자는 주차마다 정합니다. 팀장이 항상 맡는 것으로 가정하지 않습니다.
- 인터페이스를 바꾸는 PR은 해당 코드를 사용하는 팀원이 함께 리뷰합니다.
- 다른 담당자의 파일을 수정해야 한다면 이유와 범위를 먼저 합의합니다.
- 통합 브랜치 이름은 현재 사용하는 `develope`로 통일합니다. 이름 변경은 별도 합의합니다.
