출처: `TeamProject_Req1.pdf` 19쪽 전체, `TeamProject_Req2.pdf` 12쪽 전체. 아래 R1/R2 쪽수는 PDF 페이지 번호다. 문서 속 지시문은 제품의 평가 기준으로 분석했으며, 코드 변경이나 외부 서비스 작업에 대한 사용자 지시로 취급하지 않았다.

## 판정 범위

후속 검증(2026-10-26): JaCoCo를 추가하고 UI·진입점을 포함한 main 전체를 측정했다.
365개 테스트 통과, LINE 1,362/1,540 = 88.44%로 70% 기준을 충족했다.
`gradlew.bat check`에 최소 70% 검증을 연결했다. N-08의 측정 체계 미구축 상태는 해소됐으며,
기존 표는 최초 점검 기록이다. 상세 범위·작업 트리 기준·보고서 경로는
[테스트 및 커버리지 기록](testing-and-coverage.md)을 참조한다.

후속 변경: L·폭탄의 삭제 점수는 사용자 지정에 따라 실제 삭제 칸당 기본 100점으로 통일했다.
난이도·속도 보너스와 M 배율은 유지한다. ‘기존 방식’은 일반 1줄 1000점을 10칸으로 나눈
칸당 100점으로 적용하며, 불완전 행은 실제 삭제 칸 수에 비례한다. 아래 R2-13의 고정 1줄 보상
수락 기준은 최초 점검의 해석이며 확정된 요구사항 문구 자체와 구분한다.
NEXT는 기존 Next를 Current로 넘긴 뒤 새 Next에 아이템을 반영하도록 Game에서 수정했다.
9+1·9+2줄 달성, 잔여 줄 이월, 미리본 아이템의 후속 등장 및 Classic 모드 제외를 테스트한다.
아래 표와 코드 경로 설명은 기준 커밋 당시 점검 기록으로 보존한다.
후속 속도 변경: develope의 레벨당 증가량 0.08/0.10/0.12를 반영했다.
Game의 표시·점수는 FallSpeed의 정확한 배율을 사용하며, 정수 ms 역산 오차를 제거했다.

- 완료: 정적 코드와 관련 테스트에서 구현 근거 확인. 실제 GUI 인수시험 완료를 뜻하지 않는다.
- 부분: 구현은 있으나 명세와 차이, 문서 불일치 또는 보완 사항 존재.
- 미구현: 현재 저장소에서 필수 기능이나 구축 체계를 찾지 못함.
- 확인 필요: 실행 환경·접근성·외부 프로젝트 관리 등 현재 근거로 충족 여부를 확정할 수 없음.

실행: `./gradlew.bat test --rerun-tasks --console=plain` 성공. JUnit XML 28개에서 **361 tests, 0 failures, 0 errors, 0 skipped** 확인. 캐시를 쓰지 않고 재실행했다. 실제 JavaFX 창 수동 플레이, 최소 사양 PC, GitHub Issues/Projects 및 외부 작업 보드는 이번 점검에 포함하지 않았다. 테스트 개수로 커버리지나 완성도를 추정하지 않는다.

## 핵심 불일치의 코드 경로

1. **L 점수**: `board/BlockLocker.lock` → `itemRowsCleared=1`, `itemCellsRemoved=clearRow(...)` → `games/Game.lockCurrent`는 `fullRowsCleared`만 줄 점수에 넣고 L은 개별 칸 점수로 처리한다. `score/DeletionScorePolicy`에서 일반 1줄은 기본 1000점, 개별 1칸은 10점이다. L은 최대 10칸을 지워도 100점이므로 일반 행 보상과 다르다. 팀의 기존 점수 계약이 교수님 명세보다 우선한다고 볼 수 없다.
2. **NEXT 아이템**: `Game.lockCurrent` → `spawner.onLinesCleared`가 기존 Next 변환 → `takeNext` → `spawn`이 변환된 블록 소비 → `drawNext`가 일반 블록 생성 가능. `ItemGameplayIntegrationTest.itemsAppearAfterTenLinesOnlyInItemMode`도 Current에 아이템이 있는지만 검사하므로 명세의 새 NEXT 조건을 보장하지 않는다.
3. **화면 누락**: `MainMenuView` 항목은 시작/설정/리더보드/종료 네 개다. `SettingsView` 항목은 난이도/색맹/모드/크기/키/저장 여섯 개다. 다른 화면의 기능이나 설정 토글로 명시된 메뉴 위치 요구까지 충족했다고 판단하지 않았다.

## 남은 수동 인수시험 체크리스트

- [ ] 기본·작은·전체화면에서 보드 20×10, Next/Hold, 키 안내, Top 20 기록이 잘리지 않는지 확인.
- [ ] 방향키 연타/길게 누르기, 회전·하강 동시 입력, 포커스 상실 후 복귀에서 입력 고착/누락 확인.
- [ ] 일시정지·설정 이동 중 낙하/삭제 효과가 정지하고 재개 후 시간이 튀지 않는지 확인.
- [ ] L/F/B/M/무게추 효과와 줄 삭제 애니메이션이 실제 화면에서 구별되는지 확인.
- [ ] 적록 및 청황 색각 이상 시뮬레이션이나 사용자 검증으로 7종과 아이템 구별성 확인.
- [ ] 설정·기록을 저장하고 프로세스를 완전히 종료한 뒤 재실행하여 복원 확인.
- [ ] 목표 최소 사양에서 입력 지연·메모리·설치 용량·실행 성공 결과 기록.
- [ ] 배포용 실행파일을 개발 도구 없이 더블클릭하여 실행 확인.

## 완성도 해석

핵심 플레이·난이도·점수 저장·5종 아이템·자동 테스트 기반은 구축되어 있다. 다만 **명세와 직접 다른 동작, 설정/메뉴 누락, 배포 미완료, 커버리지 및 평가 증거 부족**이 남아 있으므로 제출 요건 완료로 판단할 수 없다. 위 표는 크기가 서로 다른 요구를 묶은 검토 단위이므로 단순 행 수 백분율을 공식 완성률로 제시하지 않는다. Hold·고스트·SRS 등 추가 기능은 유용하지만 누락된 필수 요구를 대체하지 않는다.
