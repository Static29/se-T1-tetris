# 일반 모드 보드 연결

`Game`이 현재 `Block`과 `Board`를 관리한다. UI는 Game의 조작 메서드를 호출하고
`getVisibleCells()` 복사본을 표시한다. 낙하 중 블록은 화면 복사본에만 합성한다.

현재·Next·Hold는 모두 `Block` 객체를 저장한다. `getCurrentBlock()`,
`getNextBlock()`, `getHeldBlock()`은 방어적 복사본을 반환한다.
Hold·재생성 시 `spawnCopy(x, y)`로 위치·방향만 초기화하고 아이템 종류와 부착 칸을 보존한다.
`Game(Board, Supplier<Block>, GameSettings, ScorePolicy)`로 아이템 생성기를 연결할 수 있다.
기존 `Supplier<TetrominoType>` 생성자는 호환용이며 일반 Block으로 변환한다.
기존 종류 getter는 무게추일 때 null이므로 빈 Hold 판정에는 `getHeldBlock()`을 사용한다.

Next/Hold는 `PiecePreviewView.showBlock()`으로 실제 모양과 L/F/B/M 표시를 읽는다.
보드·블록·미리보기 테두리 문자는 굵은 고정폭 폰트를 사용한다.
아이템의 자동 등장 조건·효과는 아직 연결하지 않았으며, 보드 Cell에는 아이템 메타데이터를
저장하지 않는다. 무게추는 효과 연결 전까지 O 색상의 일반 점유 칸으로 표시·고정한다.

- 좌표 변환은 `Position.fromXY()`를 사용한다. 보드의 상단 2행은 숨겨진 생성 영역이다.
- 생성 원점은 y=0, x는 회전 프레임을 기준으로 가운데 배치한다.
- 회전은 `BlockRotation.tryRotate()`가 SRS 후보를 순서대로 검사한다.
- 하강할 수 없으면 즉시 고정 → lock out 검사 → 줄 삭제 → Next 생성 → block out 검사 순서다.
- Hold는 생성 위치와 회전을 초기화하고 생성 충돌을 검사한다. 고정 전에는 한 번만 허용한다.
- `advanceAfterLock()`는 기존 호출 계약을 유지하는 저수준 Next 전환 메서드다.
  직접 고정하지 않으므로 UI에서는 호출하지 않는다.
- 보드 담당 브랜치의 `FallSpeed`를 가져와 연결했다. 기본 1000ms이며 10줄마다 레벨이 오른다.
  속도(칸/초)는 1 + 레벨 × (Easy 0.8 / Normal 1 / Hard 1.2), 최소 간격은 50ms다.
  Game의 현재 간격을 UI 타이머와 점수 계산이 함께 사용한다.
  일시정지 중에는 타이머를 멈추고 화면을 떠나면 해제한다.

조작: ←/→ 이동, ↑ 시계 방향 SRS 회전, ↓ 소프트 드롭, Space 하드 드롭,
C Hold, Esc 일시정지. 게임 종료 시 영문 이니셜 3자리 선택 창을 표시한다.

아이템 모드/효과, 난이도별 등장 가중치, 고정 지연은 후속 연결 대상이다.
화면에는 점수, 난이도, 삭제 줄 수를 표시한다.

## 점수 계약

- 자동·소프트·하드 드롭은 실제 블록 하강 1칸마다 기본 10점이다.
  테트로미노의 4개 셀 각각에 10점을 주는 방식이 아니다.
  좌우 이동, 회전 보정, 막힌 하강, 고정 자체는 점수를 주지 않는다.
- 완성 줄 1/2/3/4개를 한 번에 삭제하면 기본 총 1000/2000/3000/6000점이다.
- 폭탄 등 개별 칸 삭제는 실제로 지운 칸 하나당 10점이다.
- 하강·줄 삭제·개별 칸 삭제 모두 기본점수 × (1 + 난이도 증가분 + 속도 증가분 × 10)을 적용한다.
  난이도 증가분은 Easy -0.2 / Normal 0 / Hard +0.2다.
  속도 증가분은 1000 / 현재 낙하 간격(ms) - 1이며 1% 빨라질 때마다 기본점수의 10%를 더한다.
  Hard·속도 1.1배에서는 10 × (1 + 0.2 + 1) = 22점/칸이다.
  점수마다 소수점 이하는 버린다. 줄 삭제 점수는 해당 삭제 전 속도로 계산하고 다음 하강부터 새 속도를 쓴다.
- `ScorePolicy`를 교체하면 Game을 수정하지 않고 점수표를 바꿀 수 있다.
- 아이템 담당은 효과 처리 후 `Game.recordItemCellsRemoved(count)`에 실제 삭제한
  고유 칸 수를 한 번 전달한다. 빈칸·중복 칸·줄 삭제로 이미 계산한 칸은 제외한다.
  이 메서드는 보드를 지우지 않으며, 실행 중에만 점수를 반영한다.
- 아이템이 완성 줄 삭제도 발생시키는 경우 개별 삭제와 줄 삭제가 중복되지 않도록
  효과 실행 측에서 분리해야 한다. M 배율과 5줄 이상 동시 삭제 규칙은 아직 미정이다.

## 설정과 기록

- 설정에서 Classic / Item을 선택하고 메인 메뉴와 게임 화면에서 확인할 수 있다.
  모드는 다음 게임부터 적용되며 Item의 실제 아이템 생성·효과는 아직 연결하지 않았다.
- 리더보드는 모드별 상위 20개를 각각 저장한다(최대 40개).
  좌우 키로 Classic / Item을 전환하고 게임 종료 후 해당 모드를 먼저 표시한다.
  모드 필드가 없는 기존 설정·기록은 Classic으로 읽는다.

- `GameSettings`는 난이도, 모드, 색맹모드, 화면 크기, 키 바인딩을 담는 불변 값이다.
  새 Game 생성 시 복사된 설정을 사용하며 진행 중 난이도를 바꾸지 않는다.
- 메인/일시정지 메뉴의 설정에서 화면 크기(기본/작게/전체화면), 색맹모드, 키 바인딩을 저장한다.
  이 세 설정은 현재 게임에도 반영되고 난이도·게임 모드는 다음 게임에 적용된다.
- 일반 블록 문자는 보드·Next·Hold 모두 O다. 종류 정보는 유지하며
  `TetrominoType.getColorHex(colorBlindMode)`로 일반/색맹 팔레트를 선택한다.
- 키 설정: 조작 선택 → Enter → 새 키 입력. 중복 키는 거부하고 Esc는 입력 취소다.
  기본 키 복원과 설정 저장을 지원한다. 메뉴의 방향키/Enter/Esc는 고정이다.
  영문·숫자·방향키·Space·Tab·Backspace·Delete·Home·End·PageUp/Down을 지정할 수 있다.
  기본 일시정지 Esc는 기본 키 복원으로 되돌릴 수 있다.
- 화면은 800×720 기준으로 비율을 유지해 확대/축소한다. 전체화면 해제는 설정에서 기본/작은 화면을 선택한다.
- 게임 종료 창: 좌우로 자리 선택, 위아래로 A~Z 순환, Enter 저장, Esc 건너뛰기.
- 리더보드 열은 등수·이름·난이도·점수이며 점수 내림차순 상위 20개만 저장·표시한다.
  동점은 먼저 등록한 기록 우선이고 `>`는 방금 등록한 기록이다.
- 리더보드의 Delete는 현재 모드 초기화, R은 전체 초기화다.
  확인 화면에서 Enter로 삭제, Esc로 취소하며 실제 사용자 기록은 자동 테스트에서 사용하지 않는다.
- 2026-10-26 점수 규칙 변경 전 기록은 자동 삭제하지 않는다. 비교 기준을 맞추려면 초기화 기능을 이용한다.
- 게임별 UUID로 중복 등록을 방지하며 이니셜은 로그인 계정 식별자가 아니다.
- 저장 위치는 사용자 홈의 `.tetris/settings.properties`, `.tetris/leaderboard.properties`다.
  임시 파일 작성 후 교체하며 저장 실패 시 UI에 재시도 안내를 표시한다.
  잘못된 리더보드 파일을 자동으로 덮어쓰지 않는다.

검증: 프로젝트 루트에서 `./gradlew.bat test --no-daemon`.
`GameBoardIntegrationTest`는 실제 보드와 연결한 이동, 벽/바닥 차기, 회전 실패,
고정/줄 삭제, Hold 초기화, 생성 충돌, lock out, 일시정지를 검사한다.
자동 테스트와 실제 JavaFX 화면의 수동 조작 확인은 별개다.
